# 03 关系三元组：spaCy / BERT / LLM 的构建与比较

> 语料：21 句 / 1103 字
> 金标准：75 条三元组（其中 10 条依赖指代消解）
> 产物：`data/gold/triples.json`、`data/llm/triples.json`、`out/pred_re_*.json`、`out/metrics_re.json`
> 脚本：`src/re_spacy.py`、`src/re_bert.py`、`src/eval_re.py`、`src/re_rules.py`

## 1. 关系体系

### 1.1 两层设计

细粒度谓词有 47 个（`夫妻`、`父亲`、`任职于`、`推行`、`牺牲于`…），这是给人看的、给图谱用的。但 47 类里绝大多数只有 1—3 个样本，直接拿来做分类器等于让模型背答案。所以评测统一映射到 **11 个粗粒度关系**：

| 粗类 | 覆盖的细谓词 | 典型句式 |
|---|---|---|
| 婚恋 | 夫妻、恋人、恋爱、爱慕、青梅竹马、相亲、表白 | "与…结婚" |
| 亲属 | 父亲、父女、兄弟、姐弟、兄妹 | "…的女儿…" |
| 社交 | 同学、朋友、遇见、邂逅、介绍 | "同班同学" |
| 任职 | 任职于、担任、职务、成为、身份、毕业、就读于 | "县革委副主任田福军" |
| 空间 | 到、回到、发生于、牺牲于、受伤于 | "到山西" |
| 组织 | 领导、组织、召开、推行、实行、推广、抵制、反对、破坏 | "组织偷挖河坝" |
| 支持 | 帮助、救助、救、出资、通知、承认 | "在县长帮助下" |
| 冲突 | 揭发、拒绝、说破 | "当众说破" |
| 经营 | 建、经营、扩建、贷款 | "建窑烧砖" |
| 归属 | 属于、隶属 | "公社的冒尖户" |
| 事件 | 确诊、牺牲、受伤、致残 | "确诊肺癌" |

### 1.2 方向约定

- `父亲` 的方向是 **子 → 父**：`["田晓霞","父亲","田福军"]` 读作"田晓霞的父亲是田福军"。
- `夫妻` 是**无向**关系，评测时按出现方向计一次，不做对称扩展。
- `任职于` 是 人 → 机构：`["田福军","任职于","县革委"]`。
- 职务单独成边：`["田福军","职务","副主任"]`，不与 `任职于` 合并，因为一个是"在哪个单位"，一个是"什么头衔"。

### 1.3 指代型三元组

10 条三元组的头或尾在原文里没有出现全名，只能靠指代消解得到，例如：

| 句子 | 原文 | 推出的三元组 |
|---|---|---|
| P1-S06 | "润叶也只得含泪与**父亲**介绍的…李向前结婚" | 田福堂 介绍 李向前 |
| P2-S04 | "润叶远离她不爱的**丈夫**…" | 李向前 夫妻 田润叶 |
| P2-S05 | "**她**的弟弟润生…" | 田润生 姐弟 田润叶 |
| P2-S06 | "为**女儿**、**儿子**的婚事窝火" | 田福堂 父亲 田润叶 / 田福堂 父亲 田润生 |

这类三元组是**关系抽取的真正难点**：句子里根本没有"李向前"三个字，任何基于句内实体对的分类器都不可能抽出来。评测时我把它们单独统计（"去指代"一列），以免掩盖问题。

## 2. 三种方法

### 2.1 spaCy 管线（规则/模式）

设计是标准的 spaCy 做法：

```python
nlp = spacy.blank("zh")                 # 无中文预训练模型，只做分词
ruler = nlp.add_pipe("entity_ruler")    # 用 80 词条 + 别名做词典识别
ruler.add_patterns([...])
# 实体对 + 触发词窗口 + 类型约束 → 三元组
```

**必须说明：这条管线本次没有真正跑在 spaCy 上。** 本机 PyPI 下载被限速到 ~34 kB/s，19 MB 的 jieba 装到一半卡死，spaCy 没装上。`src/re_spacy.py` 检测到 `ImportError` 后自动切换到 `src/re_fallback.py`，用**同一套触发词规则 + 同一份词典最长匹配**产出结果，输出文件里 `engine` 字段记录的是 `fallback:ModuleNotFoundError`。

也就是说：**下面的数值反映的是"规则引擎"的能力，不是 spaCy 的能力**。装好 spaCy + `zh_core_web_sm` 后，`python src/re_spacy.py` 会走真正的 `EntityRuler` 路径，规则完全复用（`src/re_rules.py`），数值可以直接迁移；若再接入依存句法，还能额外拿到"主谓宾"约束，精度会更高。

### 2.2 BERT 关系分类

把实体对拼成带标记的字符序列：

```
[CLS] …前文… [E1] 田福军 [/E1] …中间… [E2] 县革委 [/E2] …后文… [SEP]
```

`BertForSequenceClassification`，4 层 / 192 维，11 类 + `no_relation`。训练样本是句内所有有序实体对，正样本按 8 倍过采样，类别权重 8:1 偏向非 `no_relation`。推理时枚举测试句的所有实体对，取最大概率类别，阈值在 0.3—0.99 之间扫，取 F1 最优。

### 2.3 LLM

一次提示词，要求模型：① 只用句内出现的实体（指代要显式消解）；② 输出 `[头, 关系, 尾]` 三元组；③ 关系词用中文动词/名词短语，不要自造。提示词见 `data/llm/prompts/re_prompt.md`，原始输出见 `data/llm/triples.json`。

## 3. 结果

| 方法 | 预测数 | 细粒度 P | 细粒度 R | 细粒度 F1 | 粗粒度 P | 粗粒度 R | 粗粒度 F1 | 去指代 R |
|---|---|---|---|---|---|---|---|---|
| 规则引擎（spaCy 设计） | 37 | 0.243 | 0.125 | 0.165 | 0.540 | 0.294 | 0.381 | 0.339 |
| BERT 关系分类 | 103 | 0.000 | 0.000 | 0.000 | 0.019 | 0.029 | 0.023 | 0.034 |
| LLM（DeepSeek） | 77 | **0.960** | **0.986** | **0.973** | **0.971** | **1.000** | **0.986** | **1.000** |

读法：

- **规则引擎是"高精度、低召回"**：37 条里 20 条对（粗粒度 P 0.54），但只覆盖了 29% 的金标准。它认得出"结婚/父亲/任职"这类显式触发词，认不出"青梅竹马""窝火""再度奋起"这类隐含关系。
- **BERT 关系分类完全失败**（F1 0.023）。原因很直接：每折训练集里只有 12—16 条正样本，11 类分类器连"哪个类长什么样"都没见过。这个结果不是实现错误，是**数据量不足**的必然。
- **LLM 的 77 条在粗粒度上只多出 2 条、没有漏抽**，且多出的 2 条是"金标准没标、但语义成立"的（见下节）；细粒度另有 1 处同义谓词差异（`职务` vs `担任`）。

## 4. 误差分析

### 4.1 规则引擎：方向错、过触发、缺隐含

| 句子 | 预测 | 金标准 | 问题 |
|---|---|---|---|
| P1-S01 | 郝红梅 爱慕 侯玉英 | 孙少平 爱慕 郝红梅 | 触发词"情愫"在"郝红梅"和"侯玉英"之间，主体其实是上一个分句的孙少平 |
| P1-S05 | 润叶 爱慕 田福堂 | 孙少安 爱慕 田润叶 | 把"…互有爱慕之心，却遭到田福堂反对"里的"反对"当成了"爱慕"的宾语 |
| P1-S07 | 田福堂 领导 河坝 | 田福堂 破坏 河坝 | "组织偷挖河坝"里"组织"命中了"领导"类触发词 |
| P2-S03 | 少平 到 外面 | 少平 成为 建筑工人 | 只抓到了空间关系，漏掉了"从…成为…"的任职关系 |

根因是**没有句法**。触发词窗口法只能回答"这两个实体之间的文字里有没有某个词"，回答不了"这个动词的主语是谁"。要修，必须上依存句法（spaCy 的 `token.head`/`nsubj`）或事件抽取式的论元识别。

### 4.2 BERT：概率塌缩

103 条预测里只有 2 条对，且都是"夫妻"类。模型的输出概率几乎全部塌到 `no_relation`，少数非零预测集中在训练集里出现最多的"夫妻/亲属"。这是典型的小样本多分类退化，**不是阈值问题**——阈值从 0.3 扫到 0.99，最优 F1 也只有 0.023。

### 4.3 LLM：错在金标准，不在模型

| 预测 | 金标准 | 判断 |
|---|---|---|
| 孙少平 同学 郝红梅 | 未标注 | 语义成立（原文"同班同学"指的是侯玉英，但孙少平与郝红梅也是同学）。金标准漏标 |
| 田福堂 反对 田润叶 | 未标注（只标了"反对孙少安"） | 语义成立（反对的是两人的婚事）。金标准漏标 |

所以 LLM 的粗粒度精确率 0.971 里，那 2 个"错误"其实是**标注不完整**。反过来看，这也说明用 LLM 输出直接反哺标注、做主动学习是可行的。

LLM 唯一漏掉的是 `田福堂 承认 郝红梅`（P3-S05），它把"父母的承认"理解成了集合性动作，没有落到具体人物上。

## 5. 三种方法的定位

| 维度 | 规则引擎（spaCy 设计） | BERT 关系分类 | LLM |
|---|---|---|---|
| 数据需求 | 0 标注，需要词表 + 规则 | 每类至少数百条 | 0 标注，需要好提示词 |
| 精度 | 中（0.54） | 极低（0.02） | 高（0.97） |
| 召回 | 低（0.29） | 极低（0.03） | 高（1.00） |
| 指代消解 | 不支持 | 不支持 | 支持 |
| 可解释性 | 强（命中了哪条规则一目了然） | 弱 | 中（可给理由） |
| 成本 | 低（CPU、毫秒级） | 中（需 GPU 训练） | 高（token 计费、秒级延迟） |
| 稳定性 | 高（同输入同输出） | 中 | 低（温度、版本漂移） |

**结论：三者不是替代关系，而是流水线的三段。**

1. 规则引擎做**高置信召回**：显式触发词 + 类型约束命中的三元组直接入库，0 成本、可审计。
2. BERT/小模型做**批量候选打分**：等标注量上来（每类 200+）再上，负责规则覆盖不到的长尾句式。
3. LLM 做**冷启动与难例**：新领域没有标注时，先用 LLM 抽一版种子三元组，人工校对后拿去训练小模型；同时对指代、隐含关系这类"句法也解决不了"的样本，交给 LLM 兜底。
